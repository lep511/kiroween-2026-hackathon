# Spec — Weekly Summary · Requirements

Feature: every run writes a Markdown summary of the Insurgency Report it publishes
(`summary.md`), generated by Claude Opus 4.6 on Amazon Bedrock in a Lambda and Step
Functions state of its own. The frontend's Summary button shows it.

## Problem

- The three `summary.md` files in the archive (`2026-11-17/`, `2026-11-19/`, `latest/`)
  were written by hand outside the pipeline (commit `be1e1f2`). New reports get none.
- `latest/summary.md` went stale: after the 2026-11-23 run, `latest/` held the Nov 16-23
  report but its summary still described Nov 12-19. Assemble never touches that file.
- The same report behaved differently depending on how it was opened: on the initial
  load the Summary button read `latest/summary.md` (the stale one); picking the same date
  from the picker read `snapshots/2026-11-23/summary.md` (missing, button disabled).

## User stories & acceptance criteria

### 1. A summary for every report
**As a** visitor, **I want** a written digest of each week's report.
- **AC1:** Every execution that reaches Assemble writes `snapshots/{date}/summary.md` for
  the report it published, rejected batches included (their cleaned report is still
  published). The file is always named `summary.md`.
- **AC2:** The summary is generated by a new Lambda, `SummarizeFunction`
  (`pipeline.stages.summarize`), run by a new state `Summarize` between `Assemble` and
  `InvalidateCache`.
- **AC3:** It uses Claude Opus 4.6 (`global.anthropic.claude-opus-4-6-v1`) by default. The
  model is the Lambda's `SUMMARY_MODEL_ID` environment variable, set from the SAM
  parameter `SummaryModelId`.
- **AC4:** A report without strikes gets a fixed summary without a model call.

### 2. Faithful, consistent content (decision 1=a)
- **AC1:** The format matches the existing hand-written summaries: the title
  `# Weekly Cyber Incident Summary ({window})` (for example `Nov 16-23, 2026`, the 7-day
  window), a counts paragraph, `## Key takeaways`, `## Biggest incidents`, thematic
  sections, and `## Common defensive themes`.
- **AC2:** Neutral, factual English built only from the report's dossiers; never the
  machine-uprising voice (`steering/narrative-tone.md`).
- **AC3:** The output is validated before it is stored: a `# ` title and a body, at most
  40,000 characters, a code fence stripped, the title pinned to the computed one. A
  truncated answer (`stop_reason` other than `end_turn`) is a failure.
- **AC4:** A rejected batch is stated in the summary.

### 3. A summary never blocks the report
- **AC1:** `Summarize` retries twice (`IntervalSeconds 10`, `BackoffRate 2`). After that its
  `Catch` stores the error in `$.summary_error` and continues to `InvalidateCache`; the
  run's outcome (`Done` or `BatchRejectedFail`) still depends only on `accepted`.
- **AC2:** `InvalidateCache` also purges `/snapshots/{date}/summary.md`, so a rerun of the
  same date is visible at once.

### 4. One place per summary (decision 2=a)
- **AC1:** Summaries live only in `snapshots/{date}/`; nothing writes `latest/summary.md`.
- **AC2:** The frontend reads the summary of the report on screen from its dated folder,
  for the latest report too.
- **AC3:** The committed `latest/summary.md` is removed; `archive.test.ts` fails if it
  comes back, and checks that every dated summary's title names its own window.
- **AC4:** `sync-snapshots.sh` also copies dated `summary.md` files.

### 5. Least privilege
- **AC1:** The Summarize Lambda reads only `snapshots/*/snapshot.json`, writes only
  `snapshots/*/summary.md`, may invoke Bedrock models (`InvokeModel*`, `Converse*`) and
  read the bearer-token secret. No DynamoDB access.

### 6. Tests and docs
- **AC1:** Tests never call Bedrock (stub summarizer, stub agent).
- **AC2:** Steering (`tech.md`, `structure.md`, `agent-enrichment.md`,
  `narrative-tone.md`), the README and the attack-globe design describe the new step.

## Decisions (from the planning conversation)

| Question                    | Decision                                                 |
| --------------------------- | -------------------------------------------------------- |
| Generator                   | New Lambda + new Step Functions state, Claude Opus 4.6   |
| Model configuration         | `SUMMARY_MODEL_ID` env var from SAM `SummaryModelId`     |
| Format and tone             | Same as the hand-written summaries; factual (1=a)        |
| Location                    | `snapshots/{date}/summary.md` only; drop `latest/` (2=a) |
| Failure handling            | Retry twice, then continue without a summary             |
| Deploy                      | Done by the developer (3=b)                              |

## Out of scope

Summaries from the local CLI, regenerating summaries for past reports, translations, and
the sandbox flow (`sandbox/`, gitignored), which does not run the Summarize step.
