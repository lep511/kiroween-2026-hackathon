## High-level view

The ordering guard runs before any side effect at every entry point: the CLI (before the preflight, exit 4), Fetch (before any feed read), `build_report` (before any agent call), and Assemble (before publishing). Overlapping executions are documented as accepted.

A curated rebuild happens only when the pair's URL matches a stored in-window strike. It keeps its slot, counts as carried, and stays out of the discard ratio. Rebuilt strikes are still re-geolocated with their slot id, so their jitter moves when an earlier strike expires.

The IAM fix is consistent across the template, `test_statemachine.py:205-215`, the steering doc, `design.md`, and `tasks.md`.

Accumulation makes a same-day rerun idempotent for the snapshot, but not for the Timeline row. A `published` row is written unconditionally, so the rerun replaces the day's real counters.

### Timeline counters on a same-day rerun

`stages.assemble` (`pipeline/stages.py:424-433`) records the row through `DynamoTimeline.record`, which uses a conditional put only for `rejected` rows (`stages.py:166-185`). A `published` row always replaces the existing one. On a same-day rerun, Fetch (`stages.py:310-319`) passes the latest report's URLs as `known_urls`. Those URLs include the strikes added earlier that day, so nothing gets staged and `transform.assemble` returns `fetched 0, new 0, carried N`. The snapshot comes out identical, but the Timeline row now says nothing new was reported that day (confirmed). This task added the `new`/`carried`/`fetched` fields, and the Rebellion Timeline is the only day-over-day record, so the gap is in scope. Reruns are manual, so the impact is low.

### Rebuild path during overlapping executions

`drop_known` lets a stored URL through only for fully curated rows, so rebuilds normally happen only in offline mode. Rebuild detection in `assemble` (`pipeline/transform.py:218-235`) depends only on the URL. If two cloud executions overlap, Assemble may read a newer `latest/` that already holds a URL Fetch staged against an older one. That agent dossier then silently replaces the stored copy in place and counts as carried, not new (likely, only with concurrent executions). The overlap behavior the docs already accept covers this, so no action is needed beyond knowing that the counters can be off in that case.

### Test coverage

The v1 gaps are closed: `test_cli_consecutive_runs_expire_a_strike_crossing_the_window`, the previous-ahead tests for `build_report`, `assemble`, the CLI, Fetch, and Assemble (`test_stages.py:287`, `:301`), and `test_curated_rebuilds_keep_their_position_and_do_not_dilute_the_discard_ratio`. Not tested: Timeline counters on a same-day rerun after an accepted run, and IAM behavior for the missing-key read, which needs a deployed stack (`aws s3api get-object` on a missing key under the Fetch role).
