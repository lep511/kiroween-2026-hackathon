## High-level view

The skip path is a third outcome next to ok and discarded. It runs through `transform.extract_one`, `build_report`, `stages.extract` and `stages.assemble` in the same way. Skips are excluded from both the numerator and the denominator of the threshold, and they are recorded as `skipped` in the Assemble result and the Timeline row. A curated row that the agent rejects becomes a `DossierValidationError`, so it is discarded and, in the cloud, retried. The only weakness in this design is that skips have no ratio guard of their own.

The filter now has the agent's `is_incident` as a backstop. The remaining false positives, such as "Apple seizes the moment…" that matches `\bseiz` plus `\bcyber`, only cost one model call and a skip. False negatives are the more costly direction, because a real incident the filter drops never reaches the agent and leaves no trace.

Because the zero-article abort also fires when every article is skipped, a quiet news day ends in `ReportAbortedFail`. The globe keeps the previous report, and the "No machine strikes reported. For now." empty state is never published from the cloud path. The behavior is documented, and an outage and a quiet day can be told apart only by the `skipped` count on the aborted row.

### Deny-list false negatives in `is_reportable_incident`

The new title patterns run before any keyword or signal check and return `False` outright:

```python
r"^(what|how|why)\b.*\byou(?:r)?\b",  # second-person explainers
r"^top \d+\b",
r"\bto watch\b",
```

Probing the function directly: "Why your bank was hacked: inside the Example Bank breach" → `False`, and "Ransomware gang to watch: Scattered Spider hits retailer" → `False`. Both are concrete incidents. The older `^(what|how|why) (is|are|…)` pattern also rejects "What is known about the Jaguar Land Rover cyber attack", a common BBC headline shape, but that pattern predates this pass. `_emit` returns `None` without logging, so in the cloud such a drop leaves no trace in CloudWatch, the staging prefix or the Timeline. Now that `is_incident` exists, the deny-list can afford to be more permissive. Admitting an explainer costs one model call and a skip, while dropping a real incident loses a strike with no way to notice. `test_sources.py` covers non-incidents being rejected but has no negative case for a real incident that starts with How/Why or contains "to watch".

### Skips and the discard threshold

`assemble` computes `discarded / total` over ok and discarded items only. In the cloud, skipped items never reach `transform.assemble` at all (`stages.assemble` counts them and `continue`s). That is the intended R10 semantics for honest non-incidents. However, `NotAnIncident` is also the outcome when the model drifts or a prompt change makes it over-reject, and that case is never retried. With 100 live items and 90 wrongly skipped, the report publishes 10 strikes and the run looks healthy. The `skipped` count is persisted, so the signal exists, but nothing reads it.

### Test coverage

Not tested: real incidents rejected by the new deny patterns, and the real Strands path when `is_incident` is false. The schema test builds a false-verdict model only with otherwise valid fields, and the stub test feeds `attack_type="unknown"`, which the real Pydantic `Literal` would reject. Strands returns validation errors to the model for a retry inside the same call, so this costs tokens rather than causing a discard. The JSONPath data flow between states is still untested, as accepted in v1.
