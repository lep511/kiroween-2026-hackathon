# Mandatory Strands agent and Step Functions orchestration for the daily Insurgency Report (v1)

The change makes the Strands/Bedrock agent the sole, mandatory extractor and replaces the single daily Lambda with a Step Functions state machine (`Preflight → Fetch → ExtractEach Map → Assemble → PublishedChoice`). The heuristic extractor and every opt-in switch (`--use-agent`, `USE_AGENT`, `UseAgent`, `EnableAgent`) are gone. Curated overrides take precedence over the agent, and a fully curated row skips the agent. A failing article is discarded, and a run with more than 20% discards aborts instead of publishing. Feed ingestion gains a per-feed cap of 25, stricter URL rules and a deterministic non-incident filter. The shared core (`transform.extract_one` / `transform.assemble`) is reused by both the CLI and the Lambda stages, so the threshold logic exists once. Tests (173), ruff and black pass. Nothing was deployed, and `sam validate` / cfn-lint were not available.

Watch for: when many articles fail, the discarded Map items carry full Lambda error causes and can push the state past the 256 KB Step Functions payload limit (likely), so the execution dies before Assemble writes the `aborted` Timeline row. The non-incident filter matches substrings and lets obvious non-incidents through (confirmed), and the agent schema has no way to say "not an incident", so those items become fabricated strikes or discards. A run that fetches zero articles publishes an empty report over `snapshots/latest/` (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The extraction contract is now strict end to end. `StrikeDossier` requires every field except `origin_country`, and `_to_overrides` and `finalize_dossier` both reject unknown attack types, unknown severities, and any country that is a placeholder or missing from `COUNTRY_CENTROIDS`. Model or validation errors propagate unchanged. The local CLI discards the article on the first failure. The cloud run relies on the Map Retry/Catch. The cost of this strictness is that every input the agent cannot honestly turn into a dossier has to be stopped before it reaches the agent, and the filter in front of it is loose.

Step Functions moves articles between states through S3 staging objects under `staging/{date}/{execution}/`, with regex-validated keys and per-prefix S3 IAM. The weak point is the data the Map carries inline: a discarded item keeps the whole Catch error object, and those objects accumulate in `$.results` most heavily in exactly the runs that should end as `aborted`.

The publish/abort decision lives in `transform.assemble`. Total-zero runs bypass the threshold and publish an empty report. An aborted rerun for a day that was already published overwrites that day's `published` Timeline row while `snapshots/latest/` still holds the published report.

IAM for Bedrock is limited to Preflight and Extract, as the steering requires. Preflight still gets invoke/converse permissions it never uses.

<summary>Issues (6)</summary>

1. **Discard payload can exceed 256 KB** (likely). The `Discard` Pass keeps `$.error`, including the full Lambda `Cause` with its stack trace, for every failed item. Keep only `$.error.Error`, or a truncated message, so a mass-failure run still reaches Assemble and records `aborted`.
2. **Non-incident filter admits non-incidents** (confirmed). Substring checks such as `"hack"` and `"attack"` accept titles like "Kiroween hackathon winners announced" and "Top 10 cybersecurity startups to watch". Match on word boundaries and tighten the signal list.
3. **Agent cannot reject a non-incident** (likely). `StrikeDossier` has no "not an incident" outcome, and `attack_type` has no fallback value. Add an `is_incident` field, or similar, that discards cleanly without counting toward the threshold, or document that such items count as discards.
4. **Empty fetch overwrites the latest report** (confirmed). `if total and discarded / total > DISCARD_THRESHOLD` lets `total == 0` publish an empty snapshot to `snapshots/latest/`, for example when every feed fails. Treat zero fetched articles as an abort, or at least skip the `latest/` write.
5. **Aborted rerun overwrites a published Timeline row** (confirmed). Both rows use `pk="rebellion", date=<day>`, so a second, aborted execution on an already-published day replaces `published` with `aborted` while `latest/` still serves that day's report. Use a conditional put, or include the execution in the sort key.
6. **Preflight over-granted Bedrock actions** (confirmed). `PreflightFunction` gets `InvokeModel`/`Converse*` but only calls `GetInferenceProfile`/`GetFoundationModel`. Drop the invoke actions there. Extract likewise does not need the two `Get*` actions.

### Map results and the Step Functions payload ceiling

`ExtractEach` keeps the result of every item in `$.results`, and Assemble receives that array inline as its Lambda payload. A successful item returns about 200 bytes. A discarded item goes through `Catch → ResultPath: "$.error"` and then the `Discard` Pass, which copies `error.$: "$.error"` into the result (`infra/statemachine/rebellion.asl.json`, `Discard` state). For a Lambda failure, `Error.Cause` is a JSON string containing `errorMessage`, `errorType`, `requestId` and the full Python `stackTrace`. A trace through Strands and botocore runs to several KB.

With 5 feeds × `PER_FEED_LIMIT` 25 = up to 125 items, a broad failure such as Bedrock throttling, revoked model access or expired credentials mid-run produces 125 such causes. At roughly 2–4 KB each, the Map output passes the 256 KB state-payload limit. The Map then fails with `States.DataLimitExceeded`, Assemble never runs, and the Timeline gets no `aborted` row. `snapshots/latest/` stays untouched, which is the right outcome, but R10's "Timeline records the day with `status: \"aborted\"`" does not happen in the scenario it exists for. The fix fits on one line: `"error.$": "$.error.Error"`, with the cause left to CloudWatch logs. The state-machine tests in `test_statemachine.py` check the shape of the Catch but not what it passes along.

### Non-incident filter in front of a strict agent

`sources.is_reportable_incident` (applied only in `_emit`, as R3 requires) requires a cyber keyword and an incident signal, but both checks are plain substring tests over `title + summary`. `"hack"` matches "hackathon" and "HackerNoon", and `"attack"` matches any figurative use. Running the function directly gave `True` for "Kiroween hackathon winners announced" (summary "Developers attack the leaderboard at HackerNoon"), "Top 10 cybersecurity startups to watch" and "How Hackers Steal Your Passwords". The how-to deny pattern `^(what|how|why) (is|are|to|could|can|do)\b` does not catch that last one.

This matters more now because the agent contract has no exit for such input. Every `StrikeDossier` field except `origin_country` is required, `attack_type` is a `Literal` with no "unknown", and `country` must resolve to a real centroid. The model is told to stay faithful and to describe unknown details as "not disclosed". Given a hackathon announcement, it will either produce a dossier anyway (likely), which puts a fabricated Machine Strike on the globe against the "never fictionalize the facts" invariant, or fail validation. Each validation failure costs three Opus calls in the cloud and counts toward the 20% threshold. With HackerNoon and NYT technology feeds feeding up to 25 items each, noise discards can push routine runs toward an abort. Word-boundary matching (`\bhack(ed|er|ers|ing)?\b`, `\bcyber-?attack\b`) would tighten the filter. Separately, an explicit `is_incident: bool` in `StrikeDossier`, with "not an incident" treated as a skip rather than a discard, would give the agent an honest way out.

### Publish/abort edge cases in `transform.assemble`

```python
if total and discarded / total > DISCARD_THRESHOLD:
    raise ReportAborted(discarded, total)
```

`fetch_all` swallows every per-feed failure, so a network outage, a Lambda without egress, or five feeds that all time out yields `total == 0`. That skips the guard, and `stages.assemble` writes an empty `snapshot.json` / `snapshot.bin` to both `snapshots/{date}/` and `snapshots/latest/`, along with a `published` Timeline row with total 0. The old single-Lambda handler behaved the same way. The new design, though, explicitly protects `latest/` from bad runs and leaves this hole open. No test covers zero results.

The Timeline write is an unconditional `put_item` on `pk="rebellion"`, `date=<day>`. A manual rerun that aborts on a day that already published replaces the `published` row with `aborted`, so the Timeline and `snapshots/latest/` then disagree. A `ConditionExpression` on `attribute_not_exists(date) OR status <> published`, or putting the execution name into the key, would avoid this.

### IAM for the stage functions

S3 access is scoped per prefix, but Bedrock access is not. `PreflightFunction` gets the same six actions as Extract, including `InvokeModel`, `InvokeModelWithResponseStream`, `Converse` and `ConverseStream`, but `ensure_agent_ready` only calls `sts:GetCallerIdentity` (no grant needed) and `GetInferenceProfile` / `GetFoundationModel`. Extract never calls the two `Get*` actions. Splitting the statements gives each function only the actions it uses.

### Test coverage

The ASL tests are structural only (flow order, Retry/Catch parameters, substitutions). Not tested: the JSONPath data flow between states (`ItemSelector` reading `$.model_id` / `$.report_date`, `Fetch`'s `ResultSelector`, `Assemble`'s payload), which only a Step Functions local run or test-state API would exercise. Also untested are the size of discarded Map items, the zero-article run, a same-day rerun against an existing Timeline row, and false positives in `is_reportable_incident`. The current tests show that real incidents pass the filter but do not show that non-incident tech headlines are rejected.
